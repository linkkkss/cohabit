## 1. 设计原则（Hinge NFAQ 风格的本土化）

Cohabit 的产品主张是 **“先聊清楚，再住一起”**，视觉要服务“把住法讲清楚”，不是约会产品的橱窗。

| # | 原则 | 具体做法 | 反面案例（禁止） |
| --- | --- | --- | --- |
| P1 | 文字优先，不用照片承担信任 | 头像只用 6 个默认几何图形；人物信息用昵称、年级、专业、标签、Prompt 承载 | 上传真人照片、相册、滤镜、颜值评分 |
| P2 | 纸感与墨色，低饱和 | 暖白纸底 `--paper`、近黑正文 `--ink`、细灰描边 `--line`；珊瑚色只做“动作与重点” | 紫粉渐变、玻璃拟态、霓虹、纯白+大面积阴影 |
| P3 | 提问式界面（NFAQ） | 标题用问句或半句“周末我更愿意……”，正文短句、结论先行 | 营销感叹号堆叠、“速配”“脱单”“cp” |
| P4 | 边界可视化 | 红线冲突用琥珀色提示条 + 文字说明；联系方式的可见性用一句规则说明 | 用红色 × 羞辱对方、把冲突做成“拉黑”按钮 |
| P5 | 一屏一个决定 | 匹配卡只有：他是谁（画像摘要）、为什么合拍（3 条理由）、下一步（邀请/查看） | 一屏塞 12 个行动点、悬浮广告、轮播图 |
| P6 | 中文排版优先 | 中文标题 32–48px，行高 1.05–1.35，**禁止负字距**；正文 15/1.65 | 直接套用英文 76px 标题导致中文挤成一团 |

动效、阴影、渐变的使用边界见第 9 节；颜色只允许使用第 2.1 节 token，禁止在页面里写十六进制色值。

### 2.2 字体与字号

字体栈（`main.css:10-11`、`23-24`）：

```css
--font-serif: "Newsreader", "Noto Serif SC", "Songti SC", serif;
--font-sans:  "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
```

- 中文标题/人名/分数/空态主句用 `--font-serif`（衬线，编辑部气质）；正文、按钮、表单、表格用 `--font-sans`。
- 中文标题字距保持 `0` 或正字距；仅英文/数字大标题可用 `-0.03em` 级别负字距（已实现：`.display` 用 `-0.035em`）。
- 字体加载失败时依赖系统回退栈，不阻塞首屏；不引入商用 Hinge 字体。

### 2.4 动效

- 时长 120–200ms，缓动 `ease-out`（进入）/`ease-in`（退出）；禁止弹跳、旋转超过 1 圈。
- 只允许动 `opacity`、`transform`、`background-color`、`border-color`；不动布局尺寸。
- `@media (prefers-reduced-motion: reduce)` 下全部关闭过渡与动画（含骨架屏闪烁），仍保留状态变化。
- 页面切换不做整页淡入超过 200ms；列表加载用骨架屏或“加载中”文字，不用转圈超过 1s。

## 3. 栅格与断点

### 3.1 容器与栅格

- 容器：`.container { width: min(1120px, 100% - 40px); margin-inline: auto; }`（`main.css:46-50`）。
- 桌面 12 列逻辑栅格，gutter 24px；实际组件多为 2–3 列卡片网格：
  - 匹配候选 `.candidate-grid`：桌面 3 列 → ≤920px 2 列 → ≤640px 1 列。
  - 寝室 `.room-grid`：桌面 3 列 → ≤920px 2 列 → ≤640px 1 列。
  - 首页 `.hero-grid`、`.profile-grid`：桌面 2 列 → ≤920px 1 列。
- 右侧栏在 M1 不做浮层；筛选条件用 `.filter-row` 横向 chip。

### 3.2 断点表（权威）

| 名称 | 宽度 | 布局 | H1/标题 | 导航 | 操作条 |
| --- | --- | --- | --- | --- | --- |
| Desktop L | ≥1280px | 12 列，容器 1120px，留白 ≥80px | 48–76px | 顶部 sticky 72px（`AppShell` 现有） | 行内按钮 |
| Desktop M | 1024–1279px | 同上但留白收窄，卡片 3 列 | 40–48px | 顶部 sticky | 行内按钮 |
| Tablet | 768–1023px | 卡片 2 列，`.filter-row` 可换行 | 36–44px | 顶部 sticky，导航项可折行 | 行内按钮 + 主 CTA 靠右 |
| Mobile L | 641–920px | 卡片 2 列 → 1 列在 ≤640 生效；表单全宽 | 32–36px | 顶部 sticky 折叠为两行（`main.css:824`，`AppShell` ≤820px 换行） | 表单页吸底 CTA |
| Mobile S | ≤640px | 单列，左右 14px，卡片内边距 18px | 32px | 顶部两行或底部固定 Tab（M1 仍用顶部） | 吸底操作条，`env(safe-area-inset-bottom)` |

实现约定：
- 现有 CSS 只有两档媒体查询：`max-width: 920px`（`main.css:824`）与 `max-width: 640px`（`main.css:840`）。P4 新增组件时必须复用这两档，不新增第三档；如确需，先改本文。
- 920–1023px 的“平板”行为由 920px 档沿用，不单独写样式。
- 断点判定用视口宽度，不用设备类型；不使用 hover 作为唯一交互（触屏要能点）。

### 3.3 移动端细则

1. **触控目标**：按钮、chip、tab、图标按钮最小 44×44px（`.btn` 已 44px min-height；`.btn-small` 36px 仅桌面表格内使用，移动端改为 44px 或整行可点）。
2. **吸底操作条**：仅 `/onboarding` 与 `/match/:uid` 详情使用；高度 64px + 安全区，`position: sticky; bottom: 0`；出现时必须给内容区 `padding-bottom`，不得遮挡最后一张卡片或输入框。
3. **导航**：M1 使用顶部导航两行（品牌 + 4 个入口）；若后续改底部 Tab，Tab 高 56px + 安全区，且内容区底部留 72px，避免遮住“开始匹配”按钮。
4. **表单**：单列；label 在输入框上方；错误文案在字段下方，不用 tooltip 悬浮；`input` 字号 ≥16px 防止 iOS 缩放（M1 可用 15px + `font-size: max(16px, 1em)` 修正，验收以不缩放为准）。
5. **横向滚动**：筛选 chips 允许横向滚动（`overflow-x: auto`，隐藏滚动条），但页面主体不得横向滚动。
6. **弹层**：宽度 ≤ `100% - 32px`，最大 520px；按钮纵向排列，主按钮在上。
7. **表格/长列表**：M1 无表格；列表项高度自适应，长昵称/长 Prompt 截断见 6.3。

## 5. 无照片头像规范（avatar_key）

产品从第一天就不做照片上传；头像用于“区分人”，不用于“评价人”。

### 5.1 资源与命名

- 固定 6 个默认头像，key 为 `avatar-01` … `avatar-06`（与 04 §3 `avatar_key` 枚举一致）。
- 文件位置：`0.cohabit/frontend/src/assets/avatars/avatar-01.svg` … `avatar-06.svg`（M1 已提供占位几何图形，96×96 视口，`currentColor` 不参与，颜色取自 2.1 token）。
- 命名规则：`avatar-NN.svg`，两位数字，小写；新增必须先在 04 的枚举里扩展，不能只加文件。
- 格式：SVG（矢量、无外链、无脚本、无 `<image>`）；单文件 ≤4KB；提供 PNG 备用仅当邮件/导出场景需要。

### 5.2 尺寸规格

| 场景 | 尺寸 | 类名 | 说明 |
| --- | --- | --- | --- |
| 列表行/成员行 | 32px | `.avatar-sm`（P4 新增） | 只显示图形，不叠文字 |
| 卡片/导航 | 42px | `.avatar` | 默认尺寸，已有实现 |
| 详情/画像头 | 64px | `.avatar-lg` | 已有实现 |
| 空态/引导 | 96px | `.avatar-xl`（P4 新增） | 仅 Onboarding 完成页 |

- 圆形裁切；背景用 `--sand`；不得加描边阴影或“在线状态”小圆点。
- 头像与昵称间距 ≥8px；头像不得单独作为可点按钮（点击目标必须包含昵称）。

### 5.3 映射与回退

1. 服务端返回 `avatar_key`；前端按 `avatar_key` 直接映射文件，不做二次随机。
2. 缺失或未知 key：使用 `hash(uid) % 6` 得到稳定回退（同一用户永远同一头像），并上报一次 console warning（生产静默）。
3. SVG 加载失败：显示首字字形（昵称第一个字，衬线 18px）叠在沙色圆底上，不显示破图图标。
4. 同一页面同一用户只渲染一个头像实例尺寸，避免同人不同图。

### 5.4 禁止项

- 禁止照片、AI 人像、卡通人物脸、明星头像、emoji 人像。
- 禁止用性别/学院/年级决定头像颜色（避免暗示标签化）。
- 禁止头像上叠加分数、状态、皇冠、等级。
- 禁止上传入口、裁切器、“换头像”按钮（M1 与后续版本均无）。

## 6. 标签与 Prompt 的展示适配

标签和 Prompt 是“无照片”场景下最主要的辨识信息，必须 **可扫读、可截断、不可注入**。

### 6.1 标签

- 来源：03 §6 的 42 个固定标签；服务端按 `TAG_ORDER` 归一化，前端不再排序（保持服务端顺序即可）。
- 数量：画像最多 8 个；候选卡最多展示 4 个 + “+N”；详情页全展示（换行）。
- 样式：11px，1px `--line` 描边，pill；文字 `--muted`；不可点、不可删除（编辑态除外）。
- 共同标签：在匹配详情里可用 `.tag.tag-shared`（珊瑚浅底）突出，最多 3 个；列表页不突出，避免视觉噪音。
- 超长标签：标签本身 ≤4 个汉字，正常不会溢出；容器用 `flex-wrap`，禁止省略号截断标签文字（截断后语义丢失）。
- 排序稳定性：同一用户在不同页面标签顺序一致（服务端顺序）。

### 6.2 Prompt

- 来源：03 §7 的 6 个 key；每人 2–3 条；单条 1–120 字。
- 列表/候选卡：取 `PROMPT_ORDER` 第一条作为大标题（`headline`），服务端截断 60 字，前端再限 3 行；不显示 key 名。
- 详情页：按 `PROMPT_ORDER` 全量展示；每条标题用题目短名（如“周末我更愿意……”），正文 15/1.7；块间距 16px。
- 空回退：无 Prompt 时展示昵称 + 第一个标签（如“小算 · 早睡早起”），不显示“暂无简介”。
- 安全：所有用户文本按纯文本渲染（Vue 插值），禁止 `v-html`；换行转 `<br>` 需在白名单内。
- 提示：编辑页在 Prompt 输入框下固定一句“请勿填写 QQ、微信、手机号；联系方式只在双方同意后可见。”不做自动识别（03 §7）。

### 6.3 长文本与截断

| 内容 | 上限 | 展示规则 |
| --- | --- | --- |
| 昵称 | 20 字（03） | 列表单行省略；卡片 2 行内；详情全展示；不得用 `word-break: break-all` 切断中文词 |
| 学院/专业 | 50 字 | 单行省略，title 属性给全文 |
| 标签 | 4 字/个 | 不截断，换行 |
| Prompt | 120 字 | 列表 3 行截断 + 省略号；详情全文 |
| 寝室标题 | 30 字 | 单行省略 |
| 请求留言 | 200 字 | 列表 2 行；详情全文 |
| 错误文案 | — | 不截断，允许换行 |

截断统一用 CSS `-webkit-line-clamp` + `text-overflow: ellipsis`，不用 JS 截字符串（避免中英文混排误差）。

### 7.2 逐页要点

**首页 `/`**
- 只讲三件事：这是什么（先聊清楚再住一起）、怎么运作（3 步）、边界（同院同性别、联系方式解锁后才可见）。
- 主 CTA：“用校园邮箱开始”，次 CTA：“先看问卷长什么样”。未登录可见，不出现任何真实用户数据。

**登录 `/login`**
- 单卡片，最多 3 个输入；注册与登录同页切换（Tab），不新开页面。
- 验证码按钮 60s 倒计时；DEBUG 环境显示 `dev_code` 提示但不自动填入（演示时口播）。
- 错误：不说明邮箱是否存在（统一“邮箱或密码不正确”）。

**问卷 `/onboarding`（4 步）**
1. 基本资料：昵称、性别（提示“注册后不可修改”）、年级、学院、专业。
2. 硬指标 11 题：按 03 §3 分三组展示（作息 / 生活习惯 / 空间与整洁），单选整行可点。
3. 软指标 6 题 + 红线 9 条：量表 1–5 端点有文字；红线末尾“以上都不是”即空数组 + 确认。
4. 标签（3–8）与 Prompt（2–3）：标签按 6 组分组；Prompt 每条 120 字计数。
- 顶部固定完成度（20/20/30/10/10/10）；每一步可单独保存；离开不丢失已保存步骤。
- 未完成不阻断保存，只阻断匹配/邀请；提示语见 8.2。

**匹配 `/match`**
- 头部一句话说明排序与红线封顶；筛选项只保留：本学院、同性别、画像 100%（M1 固定三项，不可关闭）。
- 卡片信息优先级：分数 > 昵称 + meta > 第一条 Prompt/标签 > 动作。
- 有冲突的候选仍展示，但卡片右上角琥珀角标；不允许默认隐藏冲突候选。

**广场 `/plaza`**
- 只列 `RECRUITING` 且有空位的寝室（04 §4.3）；卡片显示编号、标题、人数/容量、状态、标签。
- 不显示成员联系方式；不显示“申请”以外的写动作。

**请求 `/connections`**
- Tab：收到的 / 发出的；每张卡显示类型、状态、对方昵称、时间、动作。
- 状态文案统一（见 8.2）；终态卡片置灰但可点开详情；contact 只在解锁态出现。

**寝室 `/rooms`、`/rooms/:code`**
- 详情：编号、状态、容量、成员、标签、动作（锁定/解锁/解散/退出/转让）。
- 房主退出按钮必须解释“需先转让或解散”，点击后弹层引导，不做静默失败。
- `ARCHIVED`/`DISSOLVED` 只读：隐藏所有写按钮，显示归档/解散时间。

**我的画像 `/profile`**
- 只读展示 + “编辑”入口；展示完成度明细与六维；联系方式单独区块（仅本人可见）。
- 不展示 `dims` 的计算公式；用一句话解释“分数用于匹配，不影响他人可见内容”。

**公开寝室页 `/r/:code`**
- 无鉴权；只允许 9 个字段（04 §4.3）；无 contact、无邮箱、无 uid；`ARCHIVED/DISSOLVED` 返回 404 页面（不显示“已归档”猜测）。

## 8. 文案规范

### 8.1 语气与事实边界

- 语气：平静、具体、像室友之间把话说清楚；不用“宝贝”“脱单”“速配”“缘分”“命中注定”。
- 称呼：用“你/你们”，不用“亲”“同学您好”式客服腔；对第三人称用昵称（不出现“该用户”）。
- 事实边界：不承诺“一定合拍”；分数解释为“画像接近度”，不是“适配概率”。
- 隐私句：涉及联系方式的页面固定一句“联系方式只在双方同意后可见。”；不出现“暂无联系方式”占位（母本禁止项）。

| `RATE_LIMITED` / `COOLDOWN` | 操作太频繁，请 {retry_after} 后再试。 | 顶部提示条 |
| `ALREADY_IN_ROOM` / `TARGET_IN_ROOM` | 你或对方已经在寝室里了，需要先处理现有寝室。 | 操作按钮旁 |
| `ROOM_FULL` | 这个寝室刚满员了。 | 操作按钮旁 |
| `ROOM_LOCKED` | 这个寝室已锁定，暂不接收新成员。 | 操作按钮旁 |
| `NOT_OWNER` / `NOT_MEMBER` | 只有寝室成员/房主可以这样做。 | 操作按钮旁 |
| 网络错误 | 网络不稳定，已保留你的输入，请重试。 | 顶部提示条 |

规则：错误文案必须给出“下一步”，不只说“失败”；不显示堆栈、SQL、`request_id` 以外的内部信息（500 可显示错误号）。

### 8.4 禁用词与禁用写法

- 禁用：脱单、速配、颜值、搭子匹配率、灵魂伴侣、命中注定、缘分、CP、室友简历、海选。
- 禁用句式：“系统为你精选了 N 位优质室友” → 改成“按画像接近度排序，共 N 位”。
- 禁止把分数称为“匹配概率/成功率”；禁止承诺“99% 合拍”。
- 禁止在公开页出现“已归档/已解散”推断文案（直接 404）。
- 禁止在通知/列表/错误里出现 QQ/微信/手机号/邮箱/真名（03 §9、04 §1.7）。

## 9. 无障碍与动效

1. 焦点：所有可交互元素有 `:focus-visible` 样式（2px `--ink` 外圈 + 2px offset），不得用 `outline: none` 裸奔。
2. 键盘：Tab 顺序 = 视觉顺序；弹层 Esc 关闭并把焦点还给触发按钮；列表卡内动作可逐个 Tab 到达。
3. 语义：图标按钮必须有 `aria-label`；头像 `alt` 用昵称；状态胶囊用文字而非仅颜色；错误框 `role="alert"`。
4. 对比度：正文 ≥ 4.5:1（`--ink`/`--paper` 约 15:1）；`--muted` 仅 ≥12px 辅助文字；珊瑚底白字按钮仅用于 14px/600 以上。
5. 动效：见 2.4；`prefers-reduced-motion: reduce` 时禁用骨架闪烁、过渡、平滑滚动。
6. 缩放：200% 缩放不出现横向滚动；文字放大后按钮不裁切（用 min-height 而非固定 height）。
7. 加载：任何 >300ms 的请求必须有加载态；失败必须有重试按钮；空态与加载态不得同时出现。
