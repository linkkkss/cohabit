# docs/ui — UI 方案目录

这里放 Cohabit 的 UI 设计提案。每一份方案一个独立子目录，编号递增，互不覆盖：

| 目录 | 作者 | 内容 | 代码位置 |
| --- | --- | --- | --- |
| `01-cohabit-concept/` | 林知夏（UI 1） | 包豪斯方向的概念站：白粉 / 深灰 / 爱马仕橙，Vue 3 + Vite，四页（首页 / 广场 / 今日匹配 / 我的画像） | 分支 `feat/ui-concept` 的 `ui-concept/` |

## 01-cohabit-concept 包含什么

- `design.md` — 完整设计规范：定位、设计原则、色彩 token、字体、栅格、组件规格、动效、四页布局、响应式、无障碍、组件来源
- `design.pdf` — 同一份规范的 A4 打印版（17 页，含目录与页码）
- `design.html` — 可直接在浏览器打开的版本（适合在线看）
- `assets/` — 效果图与规范图版（入场、首页、广场、今日匹配、我的画像、tokens 图版、品牌规范）

## 如何新增一份方案（给下一位）

1. 新建 `docs/ui/02-<你的名字或方向>/`，不要改动 `01-` 里的文件
2. 必须包含 `design.md`（或 `README.md`）说明：设计目标、与 01 的差异、关键页面截图
3. 截图放 `assets/`，建议 1440×900 PNG，文件名用页面名
4. 如果带可运行代码，放到单独分支（如 `feat/ui-concept-v2`）的独立目录，不要覆盖 `ui-concept/`
5. 更新本文件的表格，写清目录、作者、一句话说明、代码位置

## 约定

- 复用现有 token 时，在文档里注明「沿用 01」而不是重新定义一遍
- 新的颜色、字号、圆角、动效曲线要单独列表，方便后来者对比
- 截图里不要出现真实姓名、学号、联系方式；演示数据用「林同学 / 周同学」这类化名
