## 4. 口播要点（可照读，约 500 字）

1. **问题**：同学院随机分配宿舍，冲突往往来自作息、整洁、访客边界这些“事前没说清”的事。
2. **匹配**：11 + 6 + 9 的住法问卷，六维接近度排序；同院同性别、画像完整、无寝；红线冲突封顶 59 但候选不隐藏。
3. **边界**：M5 补上举报与拉黑——举报直达管理员、举报人匿名；拉黑双向不可见，进行中的请求自动关闭；已同寝不强制解散，但不能再互相邀请。
4. **隐私**：联系方式默认只有本人可见，请求同意后才在双方之间解锁；导出、通知、审计、公开页都不含联系方式；每日举报限 10 次防滥用。
5. **治理**：定时任务负责过期、归档、7/3/1 天提醒、90/180 天清理与 `member_count` 修复；管理员可筛选、禁用、强制解散、导出 CSV，所有导出写审计。
6. **可解释**：设置页能看到自己的资料、联系方式可见性和拉黑名单；规则/隐私公开可读，不用登录。

### 4.1 可口播的关键数字

- 11 道硬指标、6 道软指标、9 条红线、42 个标签、6 个 Prompt、6 个默认头像。
- 六维权重：作息 20、整洁 20、社交 15、声音 15、边界 15、开销 15；红线封顶 59。
- 举报：每人每日 10 次（`REPORT_DAILY_LIMIT=10`），reason 1–200 字。
- 维护：归档/过期批 500；已读通知保留 90 天、未读 180 天；提醒 7/3/1 天各 1 条。
- 建寝限频：每人每日 5 次；请求在途 ≤3，每 24h ≤10。
- 导出：6 类业务 CSV + 用户/画像 2 类；列白名单只含 uid，无 email/QQ/微信/手机号/token。

## 5. 失败回退预案

| 现象 | 可能原因 | 现场处理 |
| --- | --- | --- |
| 首页打不开 | 前端未启动/端口占用 | 切录屏；P1 重启 `npm run dev` |
| 登录后立刻被登出 | 代理端口与允许来源不一致 | 用 5173 正常登录；或重启后端并设 `ALLOWED_ORIGINS` 含当前前端端口 |
| 举报 429 `RATE_LIMITED` | 当日已报 10 次（彩排反复） | 换 `demo010` 账号，或 `seed_demo --reset` 后重试 |
| 举报 400 | reason 为空/超 200 字 | 填 1–200 字；空提交本身可用于演示错误态 |
| 拉黑 400 `SELF_REQUEST` | 选到了自己 | 换目标；这是保护 |
| 拉黑后候选没变 | 列表未刷新 | 刷新 `/match`；拉黑会同时关闭进行中请求 |
| 解除拉黑找不到人 | 已解除过 | `seed_demo --reset`；或改演示“拉黑→解除” |
| 设置保存失败 | 昵称/专业校验或网络 | 看表单错误；换合法值；刷新 |
| 未登录打不开 `/rules` | 路由被错误加守卫 | 确认 `/rules`、`/privacy` 为公开路由；否则用已登录窗口 |
| Admin 登录后仍在登录页 | 经 5173 代理访问（CSRF/Origin 未加白） | **直连 `http://127.0.0.1:8000/admin/`**；不要在代理端口登录 |
| Admin 没有导出/动作 | 未以 staff 登录或选错模型 | 确认 `admin@cohabit.local`；在举报/寝室/用户 changelist 顶部选择动作 |
| 强制解散被拒 | 时间窗关闭/已是终态 | 这是保护；换一间 RECRUITING 寝室说明 |
| 维护命令输出 0 | 无到期数据/已跑过 | 这是幂等；先 `--dry-run` 说明语义，再讲 cron 表 |
| 移动端出现横向滚动 | 缩放非 100% 或 DevTools 宽度不对 | 重置响应式为 375×812、缩放 100% |
| 窗口关闭 409 `WINDOW_CLOSED` | seed 窗口过期（+7 天后） | `seed_demo --reset` 重建相对窗口 |

## 8. 常见提问与回答（Q&A）

| 问题 | 回答要点 |
| --- | --- |
| 举报会告诉对方吗？ | 不会；举报只进管理员队列（Admin 举报页），举报人信息不回传给被举报人，通知里也没有举报人。 |
| 拉黑会解散已有寝室吗？ | 不会强制解散（避免影响第三人）；已同寝保持，但双方不能再互相邀请/申请，后续请求 403 `BLOCKED`。 |
| 举报会不会被刷？ | 每人每日 10 次，超限 429 并给 `Retry-After`；reason 限 1–200 字。 |
| 联系方式怎么保证不泄漏？ | 默认不可见；请求同意后在**请求详情**里对双方展示；列表、通知、公开页、CSV 导出、审计 meta 都不含；导出列白名单只到 uid。 |
| Admin 导出了什么？会不会带走隐私？ | 导出的是运营字段（uid、状态、时间、房间号等），不含 email/QQ/微信/手机号/token；每次导出写 `AUDIT_EXPORTED`。 |
| 归档/解散后数据还在吗？ | 房间终态保留历史成员快照，成员只读查看；公开页 404；成员可再入新寝。 |
| 定时任务做什么？ | 过期连接/转让、归档到期窗口、7/3/1 天提醒、清理 90/180 天通知、修复 `member_count`；命令幂等、支持 dry-run。 |
| 账号注销后呢？ | 逻辑注销：open 请求取消、房主房解散、成员身份退出、联系方式清空、令牌失效；可重复调用幂等。 |
