## 0. 判读规则

1. **来源不重复造**：02 §13 与手册 §13 的用例逐条收录，编号保持原样（`C-` `R-` `T-` `W-` `S-` `SM-` `SEC-` `WIN-` `PRIV-`），本清单只做“可执行化”（前置数据、操作、断言、阶段、执行方式），不改语义。
2. **M1 口径**：团队计划的 M1 = **基础层**（自定义 `accounts.User`、认证、画像/问卷/匹配、领域模型与迁移、前端外壳及问卷/匹配页）。它对应手册 §11.2 的 M1 可运行骨架 + M2 画像闭环 + M3 匹配闭环（能力到 **D6 checkpoint** 为止）。手册的 M4/M5/M6 在本清单中标记为 **M4 / M5 / M6**，不并入 M1 通过条件。
3. **不通过条件**：任一 M1 用例失败、任一 P0/P1 缺陷未关闭 → M1 不通过；后置用例失败不阻断 M1，但必须登记在缺陷清单。
4. 标 **`[阻塞]`** 的检查项（隐私、迁移、一人一寝约束）即使在后置阶段也必须在首次出现该能力的里程碑当轮通过，不得拖到 M6。
5. 本清单所有链接必须可解析（检查项 D-09）；引用行号以当前仓库为准。

### 2.3 执行方式

- **API 级**：`APIClient`，断言状态码 + `code` + 关键字段 + DB 副作用；每条用例独立事务回滚（除并发）。
- **并发级**：`TransactionTestCase` + `threading.Barrier` + 每线程独立 `Client`；结束 `connections.close_all()`；断言“恰好一个成功/无超员/无重复行”。
- **模型级**：迁移后直接查 `information_schema`/`pg_indexes` 或 `connection.introspection`，断言约束/索引存在；再用 ORM 尝试插入违规数据断言 `IntegrityError`。
- **UI 级**：按 §7 走查表在三档宽度逐项勾选；截图存 `docs/qa/`（本地，不提交大数据）。
- **回归**：`pytest`（后端）+ `npm run build` + `vue-tsc`（前端）+ 本清单 M1 项全绿。
