# Cohabit 模块地图（改动影响指南）

> **用途**：改代码前先回答三个问题——这块归谁管？改它会牵动谁？要跑什么、同步哪些文档？
>
> 本文不是 API/字段文档：接口细节看 [04-API契约](04-API契约.md)、[OpenAPI](openapi.yaml)，状态/锁看 [02-组寝状态机](02-组寝状态机.md)，字段/问卷看 [03-数据字典与问卷](03-数据字典与问卷.md)。
>
> **当前基线**：2026-11-18 路由收口后，后端全量 **730 passed**；前端 **270 modules**（M6F 基线，本轮未改前端）。2026-11-23 新增本图与根目录 [项目索引](../项目索引.md)。
>
> 维护规则：新增 app、页面、共享服务、契约端点时，在本图 §2/§3 加行，并在 §4/§5 补影响链；否则下一任维护者会漏改。

## 1. 一张图：请求从哪里来到哪里去

```text
浏览器
  └─ Vue 页面/组件（views/、components/）
       └─ src/api/*.ts（axios 封装）
            └─ src/api/client.ts（JWT、refresh、统一错误）
                 └─ Django URL（config/urls.py → app/urls.py）
                      └─ View（views.py）
                           └─ Serializer（serializers.py，输入校验/输出字段）
                                └─ Service（services.py，事务/锁/状态/副作用）
                                     ├─ Model（models.py）→ PostgreSQL
                                     ├─ Notification（通知）
                                     └─ AuditLog（审计）
                      └─ Response → 前端状态/页面

Django Admin（*/admin.py）
  └─ Admin action / 自定义 view
       └─ Service / lifecycle / maintenance
            └─ Model + AuditLog

cron / 运维命令
  └─ core/management/commands/*
       └─ adminops/maintenance.py
            └─ connections/rooms/notifications services
```

**结论**：View 只做 HTTP 适配，状态与副作用在 Service；改 Service 的影响通常大于改 View。Admin 和 cron 也复用同一批 Service，不能只测学生端。

### 2.2 模型与 app 归属

- **accounts**：`User`、`InviteCode`、`ContactInfo`。联系方式不在 profiles，改联系方式字段先看 accounts。
- **profiles**：`Profile`。问卷/画像 JSON、完整度、标签/红线都在这里。
- **connections**：`ConnectionRequest`。关闭原因、状态、超时、确认阶段都在这里。
- **rooms**：`Room`、`RoomMember`、`RoomTransfer`。`member_count` 是寝室表的冗余计数，必须与成员状态一致。
- **notifications**：`Notification`。
- **adminops**：`TimeWindow`、`Report`、`Block`、`AuditLog`。
- **core**：`BaseModel`（统一 id/created_at/updated_at）；不是业务表。

## 4. 关键链路：改一块会牵动哪里

### 4.1 身份、角色与权限链

```text
accounts.User（role/status/college/gender）
  ├─ 认证/JWT/refresh → 所有 /api
  ├─ permissions.py（学生端写操作只允许 STUDENT）→ connections/rooms 动作
  ├─ lifecycle.py（禁用/注销级联）→ connections/rooms/ContactInfo/AuditLog
  ├─ matching（同学院/同性别）→ 候选
  ├─ rooms（成员/房主）→ 详情/动作/公开页
  └─ Admin（disable_users/export_users_csv）
```

改动 `User` 字段、`role` 或 `permissions.py` 时，至少检查：accounts 全部认证测试、rooms/connections 的 `test_role_guard.py`、Admin 禁用级联、seed、前端 auth/守卫。

### 4.2 画像 / 问卷链

```text
03 题库/标签/红线
  → profiles.constants/dims/validation
  → Profile JSON（dims/tags/prompts）
  → completeness
  → matching.algorithm（六维、标签、红线）
  → match 列表/详情
  → onboarding/profile 前端
  → seed 画像
```

改字段/常量会同时影响：问卷前端、完整度阈值、匹配分数、seed 自检、06 匹配用例。**先改 03，再改常量/校验，最后跑 matching + profiles + seed。**

### 4.3 匹配链

```text
Profile 完整度 + 性别/学院 + 无寝 + 拉黑排除
  → matching.candidates
  → matching.algorithm（六维 + 共同标签 + 红线封顶 59）
  → /api/match 列表/详情/score
  → MatchPage/MatchDetailDialog
```

改候选条件会影响“谁能被看见”；改算法会影响所有排序/分数和 seed 断言。红线冲突是展示但封顶，不是隐藏；不要改成“直接过滤”。

### 4.4 组寝请求链（高风险）

```text
匹配详情发起邀请 / 寝室邀请 / 申请
  → ConnectionRequest（PENDING）
  → 对方同意（CONTACT_SHARED）
  → 双方两步确认（CONFIRMING → CONFIRMED）
  → rooms.create_room_for_pair（事务 + 锁）
  → Room/RoomMember + 通知 + 审计
```

改状态、动作、超时（请求 48h/联系方式 7d/确认 48h）、关闭原因或 `actions`，必须同步：
- [02 §3](02-组寝状态机.md) 与 [04 §4.4](04-API契约.md)；
- `connections/services.py` 和前端 `connectionFormat.ts`/`ConnectionActions.vue`；
- 通知类型、审计、seed、`test_flow`/`test_confirm`/`test_concurrency`；
- 拉黑副作用（`CANCELLED/BLOCKED`）、禁用级联。

### 4.5 建寝与寝室链（高风险）

```text
connections.confirm（双方）
  → rooms.create_room_for_pair（owner/成员/容量/性别/学院；日限 5）
  → Room + RoomMember（一人一寝唯一约束）
  → 通知/审计
  → 广场/详情/公开页
  → 锁定/解锁/解散/退出/移除/转让/归档
```

改 `Room.status`、`member_count`、成员状态、容量、归档/解散语义，会影响：
- 广场筛选、详情动作、公开页 404/字段；
- 转让（24h、房主退出前必须转让或解散）；
- Admin 删除保护/强制解散；
- `repair_member_count`（只修非终态）、归档快照；
- seed 的 6 寝/20 成员/2 转让断言；
- 02 §4–6、04 §4.3、06 R/T 用例。

### 4.6 时间窗链

```text
TimeWindow（按学院唯一，start<end）
  ├─ core.timewindow.require_window_open → 组寝写操作（创建/同意/确认/寝室动作）
  ├─ GET /api/timewindow → 前端 TimeWindowBanner
  └─ cron archive_rooms / send_window_reminders
```

时间窗只约束**组寝写**；注册/登录/资料/问卷/举报/拉黑/已读不受影响。改窗口语义要同步 02 §7、04 §1.8/§4.7、06 W 用例、前端横幅、cron；`TimeWindowAdmin` 不允许删除，只改时间。

### 4.7 通知链

```text
业务服务 → notifications.services.notify（类型/标题/链接/收件人）
  → Notification
  → /api/notifications + 前端格式化/角标
  → 03 §9 通知字典
```

新增/修改通知类型会影响：前端 `notificationFormat.ts`、通知中心跳转、seed 的 79 条断言、Admin 筛选/导出、通知清理（已读 90 天/未读 180 天）。通知正文**不得含联系方式**。

### 4.8 审计链

```text
业务动作 → core.audit.write_audit(action, target_type, target_id, actor, meta, request_id)
  → AuditLog
  → Admin 筛选/导出（AUDIT_EXPORTED）
  → 06 S-10 / 管理员手册
```

改 action 名、target_type、meta 结构会影响 Admin 筛选、CSV、测试断言和审计口径。`normalize_target_type` 会把小写别名统一成大写；写审计必须与业务状态同事务（S-10）。

### 4.9 隐私 / 举报 / 拉黑链

```text
ContactInfo（accounts，数据库明文保存；API/Admin 按权限脱敏展示）
  ├─ profiles 联系方式 API（仅共享后 + 开关）
  ├─ connections 详情（CONTACT_SHARED 后）
  ├─ adminops Block（双向不可见；关闭 open）
  ├─ rooms/matching 可见性
  └─ Admin Report target_contacts（每次 ADMIN_VIEW_CONTACT）
```

改这里最容易产生“联系方式泄漏”。必须跑：联系方式零泄漏扫描、block 双向可见性、已成立寝室不自动解散、解除拉黑不恢复旧请求、Admin CSV 白名单、`ADMIN_VIEW_CONTACT` 审计。举报**不自动封禁、不通知被举报人、无列表端点**。

### 4.10 Admin 链

```text
Django Admin（各 app admin.py）
  ├─ actions（disable_users/force_dissolve_rooms/mark_resolved/...）
  ├─ 自定义 view（Report target_contacts）
  ├─ CSV 导出（白名单，写 AUDIT_EXPORTED）
  └─ 模型保存/删除保护（R-21、S-06）
```

Admin 不能代替学生 confirm/accept（S-06）；删除有 ACTIVE 成员的寝室拒绝（R-21）；联系方式查看要 `has_change_permission` 并写审计；CSV 不含 email/密码/QQ/微信/手机/token。

### 4.11 seed / 演示链

```text
seed_demo --reset
  → 41 用户 / 40 画像 / 40 联系 / 6 寝 / 20 成员 / 8 请求 / 2 转让 / 79 通知 / 2 窗口 / 2 举报 / 4 拉黑 / 10 审计
  → 06 基线、07 演示、管理员手册、截图
```

改模型/枚举/状态/通知/计数，必须同步 [seed-spec](seed-spec.md)、[03 §11](03-数据字典与问卷.md)、[06 各里程碑](06-验收清单.md)、[07](07-演示脚本.md)。额外 ADMIN 现在是允许的，`--reset` 不会因多一个 ADMIN 失败。

### 4.12 前端壳 / 认证链

```text
main.ts → App.vue → AppShell
  ├─ router guard（auth.ensureReady）
  ├─ auth store（refresh/clear）
  ├─ NetworkNotice / TimeWindowBanner / UserMenu
  ├─ route error / ErrorBoundary / 404
  └─ 所有 views
```

## 9. 已知地雷与易错点

1. **`GET /api/rooms/:id` 已收紧为 404**（2026-11-18）。`GET` 只用 9 位 code；`PATCH`/动作只用内部 id。不要为了“兼容”恢复，否则 04 §4.3 与 `test_route_resolution.py` 会冲突。
2. **历史 `.walkthrough/qa_m5_api.py` 仍按旧 GET-by-id 断言**；复用前改为 `room.code`，不要把它当作当前契约证据。
3. **`member_count` 的归档快照**：`repair_member_count` 只修 RECRUITING/FULL/LOCKED；ARCHIVED/DISSOLVED 的计数是历史快照，不能重算。seed 归档房 #5 的 6/6 就是验证点。
4. **confirm 响应 room 快照**：`_establish_room` 后要 `refresh_from_db`，否则响应 2/DB 3；这是 M4 的回归点。
5. **CONFIRMED 的 `expires_at` 必须为 NULL**；不要再写占位过期时间。
6. **举报不自动封禁、不通知被举报人、无列表端点**；拉黑不自动解散已成立寝室，解除拉黑不恢复旧请求。
7. **Admin 不能代替学生 accept/confirm**（S-06）；学生端写动作只允许 `role=STUDENT`。
8. **Admin 删除有 ACTIVE 成员的寝室**：`has_delete_permission=False`，`delete_model/delete_queryset` 提示 `MUST_DISSOLVE_BEFORE_DELETE`；这不是学生端 API 409（R-21 口径差异）。
9. **联系方式只能通过受控路径出现**：共享后 + 本人开关；Admin 仅逐次 `target_contacts` 查看并写 `ADMIN_VIEW_CONTACT`；任何 CSV 不得含 email/QQ/微信/手机/token。
10. **时间窗只约束组寝写**；关窗时资料/问卷/举报/拉黑/已读仍可用。`TimeWindow` 每学院唯一、start<end、不能删除。
11. **`College` 不是表**：`docs/ER-v2.md` 的 College 只是 `User.college`/`TimeWindow.college` 值域；不要为它建 migration。
12. **seed 额外 ADMIN 允许**：`--reset` 只校验种子 admin 的唯一性；不要再写成“总 ADMIN 必须为 1”。`DEBUG=false` 时 `seed_demo` 会拒绝，除非 `--force`；生产库拒绝。
13. **`.walkthrough/` 是临时证据**，不是交付代码；不要把它当产品依赖或提交入口。
14. **README/手册的 721 是 M6F 时点**；当前全量 730。新增改动后更新 06/08/日记，不要在 README 历史段落里伪造新数字。
